# Premium feature: upload your own card designs

Research notes on how to implement and ship a "premium: upload your own card designs" feature in a mobile multiplayer card game (iOS and Android).

Note: several source domains (support.google.com, sightengine.com, playingcards.io, kb.tabletopsimulator.com, help.tabletopia.com) could not be fetched directly during research; those facts come from search snippets and secondary sources and should be re-verified before relying on them.

## 1. Precedents

| Product | Model | Specifics |
|---|---|---|
| **Tabletop Simulator** | Sprite-sheet upload | Grid 2x2 up to 10x7 (70 slots; slot 70 reserved for the hidden/back image), sheet downscaled if any edge >4096 px; ~400x560 px per card is the community "sweet spot". Assets hosted on Steam Cloud/imgur URLs; other players fetch on table load and keep a local "Mod Cache"; expired links break the game for new players (lesson: host images yourself, never by user URL). [ShuffleKit guide](https://shufflekit.com/blog/how-to-make-custom-cards-tabletop-simulator), [Observable dimensions](https://observablehq.com/@visnup/tabletop-simulator-custom-deck-dimensions), [TTS asset importing](https://kb.tabletopsimulator.com/custom-content/asset-importing/) |
| **Tabletopia** | Per-component images in a Workshop | JPEG/PNG, max 4000x4000, 10 px = 1 mm, front and back must be identical pixel size. [Preparing Graphics](https://help.tabletopia.com/knowledge-base/how-to-prepare-graphics/) |
| **PlayingCards.io** | Deck template + card data (CSV) with text/image layers; images referenced by direct URL. [Custom Decks doc](https://playingcards.io/docs/custom-decks) |
| **Dulst** | Upload or paste URL; server auto-fits image to the game's configured card size (a good template-fit precedent). [Dulst Card Art wiki](https://dulst.com/dulst/wiki/Card-Art) |
| **Board Game Arena** | No custom art; only a profile avatar, and only after 20 games played (an anti-abuse gating idea). [BGA on X](https://x.com/BoardGameArena/status/1294251577168060416) |
| **MakePlayingCards** | Print flow: template download, upload, crop, safe-zone overlay, preview. 63x88 mm poker; 1/8" bleed + 1/8" safe margin (~36 px each at 300 dpi); 825x1125 px with bleed. [MPC 63x88](https://www.makeplayingcards.com/design/custom-blank-card.html), [MPC upload tips](https://www.makeplayingcards.com/pops/faq-photo.html) |
| **Marvel Snap / Hearthstone** | Curated only. Snap "Custom Card" (Mar 2024) only remixes owned borders/finishes; variants sell for 700 / 1200 gold (~$10-15). Hearthstone card backs/skin bundles ~1500 Runestones ($14.99; 100 Runestones = $1). [Snap custom card](https://marvelsnapzone.com/custom-card/), [Snap variant prices](https://www.pockettactics.com/marvel-snap/variant), [HS Runestones](https://upcomer.com/everything-to-know-about-runestones-in-hearthstone/) |
| **Discord Nitro** (premium-UGC model) | Uploads are free per server (50 static slots), Nitro pays for *portability* (use anywhere) and animated slots. Files <=256 KB, JPEG/PNG/GIF/WEBP; guidelines: no violence/adult, "make sure you have the rights". [Discord custom emoji](https://support.discord.com/hc/en-us/articles/360036479811-How-to-Add-Custom-Emojis-on-Discord), [Nitro](https://support.discord.com/hc/en-us/articles/115000435108-What-are-Nitro-Nitro-Basic) |

Takeaway UX: pick template -> pick image -> crop with fixed aspect + safe-zone overlay -> optional text/logo -> live preview (front/back, flip) -> save deck -> share to friends/room. The Discord pattern (creation free, *usage everywhere* premium) is the strongest monetization analogue.

## 2. Mobile card-editor UX

- **Aspect ratio**: poker 63x88 mm (2.5x3.5", ratio 1:1.4); bridge 57x88 mm. Use 5:7 as the crop lock. Render at 2x/3x: e.g. 750x1050 master, plus 375x525 and 188x263 variants. Templates: [Mr. Playing Card dielines](https://www.mrplayingcard.com/templates), [Euro poker safe-area PDF](https://printplaygames.com/wp-content/uploads/Templates/CARDS/EuroPoker/Euro%20Poker%20Cards%20(63mm%20x%2088mm)%2018%20per%20sheet.pdf).
- **Safe zone**: keep rank/company identity/pips in a locked frame the user can't alter; user art only fills the "art window" (Dulst/Snap-style). Reserve ~5% margin so rounded corners and the frame never clip faces.
- **Crop libraries**: Flutter `image_cropper` (native uCrop/TOCropViewController, `aspectRatioPresets`), `crop_your_image`, `crop_image` ([pub.dev image_cropper](https://pub.dev/packages/image_cropper), [crop_your_image](https://pub.dev/packages/crop_your_image)); React Native `react-native-image-crop-picker` (native crop UI, fixed ratio, compression) ([npm](https://www.npmjs.com/package/react-native-image-crop-picker)); Unity `yasirkula/UnityImageCropper` (uGUI, `selectionMinAspectRatio/MaxAspectRatio`) ([GitHub](https://github.com/yasirkula/UnityImageCropper)).
- **Overlays**: 1 text field (deck name/initials) + optional logo slot, constrained fonts/colors; composite server-side so the same PNG serves all clients.
- **Generation**: one upload -> card back; card faces = frame + art window + rank glyph layer. Preview with a simple 3D flip (Flutter `Transform` + `AnimationController`, RN Reanimated rotateY, Unity quad). Show the deck fanned and in-hand at real in-game scale before purchase/save.

## 3. Technical pipeline

- **Limits**: accept JPEG/PNG/HEIC/WebP up to ~10 MB and 4096 px; reject smaller than ~600x840. Store master as PNG/WebP lossless; serve WebP (decodable everywhere you target). AVIF only on iOS 16+ and buggy on Android 12-13 decoders, so not worth it yet ([AVIF iOS 16 fix](https://tylergaw.com/blog/ios-16-avif-fix/), [mobile formats](https://medium.com/@adi.mizrahi/the-best-image-format-for-mobile-applications-5fa9c9bdc2f4)).
- **Resizing**: generate 3 variants at upload (or on-the-fly via imgproxy, self-hosted, or Cloudflare Image Transformations: 5,000 free/month then $0.50 per 1,000; storage $5 per 100k images) ([imgproxy](https://imgproxy.net/), [Cloudflare pricing](https://theimagecdn.com/docs/cloudflare-images-pricing)).
- **Dedupe**: SHA-256 of the normalized master -> content-addressed key `decks/<hash>.webp`; identical uploads share storage and moderation verdicts; immutable URLs enable infinite CDN/client cache TTLs.
- **Distribution**: deck manifest (deck_id, hash, variant URLs, byte sizes) sent in the room state at lobby time; clients prefetch before "Ready" is enabled; stream medium variant first, full-res lazily; hard timeout (e.g. 5 s) then fall back to the default deck with a small badge "custom deck unavailable". Tabletop Simulator shows why: URL-hosted assets that expire break for newcomers, so always host on your own CDN ([TTS asset loading thread](https://steamcommunity.com/app/286160/discussions/0/4086396791259715839/)).
- **Budget**: for a Startups-sized deck (~40 faces + back, six company designs) at 375x525 WebP q80 ~ 25-40 KB each = ~1.5 MB per deck; cap per-room custom decks (e.g. host only, or <= 4) to keep lobby downloads under ~5 MB. LRU disk cache ~100 MB; offline play uses cached decks only.

## 4. Moderation and policy

- **Apple guideline 1.2** (verbatim requirements): a filtering method, report mechanism with timely response, block abusive users, published contact info; you must remove violating content or risk removal. Reviewer expectation is action on reports within 24 h ([Apple guidelines](https://developer.apple.com/app-store/review/guidelines/), [BuddyBoss 1.2 notes](https://buddyboss.com/docs/app-store-guideline-1-2-safety-user-generated-content/)).
- **Google Play UGC**: terms of use, in-app report + block, automated moderation expected at scale, safeguards so monetization doesn't encourage objectionable behavior ([Play UGC policy](https://support.google.com/googleplay/android-developer/answer/9876937?hl=en), [moderation requirements](https://support.google.com/googleplay/android-developer/answer/12923286?hl=en)).
- **Needed features**: pre-publish automated scan (block on high-confidence nudity/gore/hate symbols, queue on medium); "Report deck" on any card face; block player (hides their decks too); admin queue with approve/reject/ban; strike + repeat-infringer termination; ToS clause forbidding infringing/objectionable art; EULA acceptance at first upload.
- **API pricing** (image, per 1,000): AWS Rekognition ~$1.00 ([AWS](https://aws.amazon.com/rekognition/pricing/)); Google Vision SafeSearch $1.50 (first 1,000/month free) ([GCP](https://cloud.google.com/vision/pricing)); Sightengine free 2,000 ops/mo, $29 for 10k, overage $0.002 ([Sightengine pricing](https://sightengine.com/pricing), [summary](https://checkthat.ai/brands/sightengine/pricing)); Hive ~$3, no public pricing, self-serve capped ~100 req/day ([Hive](https://thehive.ai/pricing)). At 100k uploads/month the bill is $100-300; negligible versus premium revenue.
- **DMCA**: register a designated agent with the US Copyright Office ($6, renew every 3 years), publish it in-app/website, implement notice-and-takedown plus a repeat-infringer policy to keep section 512(c) safe harbor ([Copyright Office directory](https://www.copyright.gov/dmca-directory/), [FAQ](https://www.copyright.gov/dmca-directory/faq.html)). Expect uploads of Pokémon/Marvel/sports logos; consider a lightweight logo-detection pass.
- **COPPA / age**: photos are personal information under COPPA; the amended rule took effect June 23 2025 (compliance April 22 2026). If any under-13 users are known, uploads require verifiable parental consent, so gate the feature at 13+ (or 16+ in EU) via declared age; Apple 5.1.4 also requires a privacy policy for apps that collect photos from minors ([FTC COPPA FAQ](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions), [Federal Register 2025 rule](https://www.federalregister.gov/documents/2025/04/22/2025-05904/childrens-online-privacy-protection-rule)).
- **Public matchmaking**: recommendation: custom decks render only in private/friend rooms, or the host's deck only, plus a per-user "Show others' custom decks" toggle (default off in public queues). This shrinks the moderation surface, avoids surprise content in random matches, and gives a Snap/Hearthstone-style curated look to ranked play.

## 5. Premium tier

- **Store rules**: digital unlocks must use IAP (Apple 3.1.1); subscriptions must give ongoing value, last >= 7 days, work across all the user's devices, and offer a restore mechanism; free trials via introductory offers (one per subscription group) or a "XX-day Trial" tier-0 non-consumable for one-time products; Family Sharing is optional for auto-renewables and non-consumables (up to 5 members) ([Apple guidelines](https://developer.apple.com/app-store/review/guidelines/), [Apple subscriptions](https://developer.apple.com/app-store/subscriptions/), [Family Sharing tech talk](https://developer.apple.com/videos/play/tech-talks/110345/)).
- **Pricing precedents**: single curated cosmetic $10-15 (Snap variant, Hearthstone card-back bundle). Discord Nitro Basic ($2.99/mo) is the direct analogue for "portable UGC". Suggested: **one-time $4.99-9.99 "Designer" non-consumable** (1-3 deck slots, usable in private rooms) plus optional **$2.99/mo Plus** that adds more slots, AI generation credits, and showing your deck in public matches. A one-time unlock reviews cleaner and matches a cosmetic; a subscription only if you keep adding ongoing value (new frames, AI credits).
- **Cross-platform entitlements**: RevenueCat (free to $2.5k MTR, then 1%), Adapty (free to $5k, 1%), Qonversion (free to $10k, 0.6% but $99/mo minimum). All do server-side receipt validation, entitlements, and webhooks ([comparison](https://theswiftk.it.com/blog/revenuecat-vs-adapty-vs-qonversion-ios)). The game server should call the provider's REST API or consume webhooks and store `entitlement.designer = true` on the player record; the upload endpoint and the room "use custom deck" flag check that server-side, never the client.

## 6. AI-generated card art as premium

- Precedent: Roblox Photo-to-Avatar APIs and many "AI game asset" apps; the card-game industry shows real backlash (MTG's anti-AI stance, Star Realms/Draconis 8, Champions TCG's $90k "AI artist") ([Slate on MTG](https://slate.com/technology/2024/08/magic-the-gathering-artificial-intelligence-card-art-controversy.html), [BoardGameWire](https://boardgamewire.com/index.php/2024/11/07/star-realms-maker-wise-wizard-games-defends-using-ai-art-in-new-projects-board-game-artists-call-out-ethics-of-decision/), [PC Gamer](https://www.pcgamer.com/games/card-games/champions-tcg-ai-artist/)).
- Policy: Google Play requires an in-app flag/report button for offensive AI output and holds you responsible for what it generates ([TechCrunch](https://techcrunch.com/2023/10/25/google-plays-policy-update-cracks-down-on-offensive-ai-apps-disruptive-notifications/), [Play AI content policy](https://support.google.com/googleplay/android-developer/answer/14094294?hl=en)). Apple 5.1.2(i) (Nov 2025) requires disclosure and explicit consent before sending personal data (e.g. selfies) to third-party AI ([Apple guidelines](https://developer.apple.com/app-store/review/guidelines/)). Pure AI output has no US copyright, so you can't protect the resulting art, and FTC deception rules apply if you market it as hand-made ([Promise Legal risk map](https://blog.promise.legal/ai-game-assets-three-layer-risk-map-2026/)).
- Recommendation: ship AI as a *second* phase, credit-based (consumable IAP), prompt-only (no photo-of-person input), with prompt filtering + output moderation (same pipeline as uploads), an "AI-generated" badge, and a visible report button.

## Shipping order

1. Upload + crop + template render + private-room-only display, moderation pipeline, report/block, DMCA agent, one-time IAP via RevenueCat.
2. Sharing/gifting decks to friends, deck gallery.
3. Public-match opt-in and subscription tier.
4. AI generation credits.
